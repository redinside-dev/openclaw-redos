# ENG Research — AI Coding Agent Landscape (2026-02-24)

## Executive Summary
Researched three leading autonomous coding agents: **Devin AI v3.0**, **OpenHands**, and **SWE-agent**. Key findings inform Phase 5 (push/PR creation) design for the coding factory.

## Devin AI v3.0 (Cognition AI)

### Architecture
- **Swarm of specialized models** in sandboxed environment (terminal, code editor, browser)
- **Four-phase loop**: Planner → Coder → Critic → Browser
- **Closed-loop autonomy**: Repeats until success or human intervention

### Key Components
1. **Planner** (high-reasoning model): Decomposes requirements, generates step-by-step strategy, re-plans on roadblocks
2. **Coder** (code-specialized): Generates/edits code, learns frameworks via docs, handles multi-file changes
3. **Critic** (adversarial): Reviews for security, logic errors, test failures before execution
4. **Browser**: Scrapes/synthesizes documentation (APIs, StackOverflow)

### Workflow
1. Task input → Planner researches codebase (up to 10M+ tokens), outlines plan
2. Coder implements in sandbox; Critic validates
3. On failure: loop restarts with error logs; Planner re-strategizes
4. Output: PRs with descriptions; responds to reviews; integrates GitHub/Jira/Slack
5. Monitoring: Parallel agents handle multi-tasks; repo indexing every few hours

### Strengths
- High autonomy for complex tasks (legacy migrations, refactors)
- Self-healing on errors
- PR generation + review integration

### Limitations
- Latency on complex reasoning (minutes to start)
- Compute costs (~$0.10/minute)

## OpenHands (formerly OpenDevin)

### Architecture
- **Composable multi-agent system** (Python SDK core)
- **Model-agnostic**: Works with Claude 4, Devstral, GPT, others
- **Sandboxed runtime**: Docker/Kubernetes (self-hosted or cloud)
- **Full auditability**: Shell session control, no host access

### Key Components
| Component | Purpose |
|-----------|---------|
| SDK | Python library for building/orchestrating agents |
| CLI | Terminal tool powered by any LLM |
| Cloud | Web-based for complex planning/execution |
| Daytona Middleware | Agent-agnostic infra for instant starts, multi-instance runs |

### Capabilities
- Autonomous code exploration, testing, PR generation
- Excels in outer-loop automation (beyond code completion)
- Integrations: GitHub, GitLab, Slack, CI/CD, APIs
- Scalability: Single tasks to thousands of parallel agents

### Performance
- **OpenHands Index**: Live leaderboard on real software tasks
- Reported: 87% same-day bug fixes
- 65K+ GitHub stars, $18.8M funding (as of 2026)

### Strengths
- Open-source + transparent
- Model-agnostic (choose your LLM)
- Enterprise-ready with integrations
- Full autonomy in sandboxes

### Limitations
- Relies on code review for context (e.g., license compliance)
- First-gen agents less sandboxed (improving)

## Implications for Coding Factory Phase 5 (Push/PR Creation)

### Design Decisions
1. **Critic model**: Implement a validation gate (similar to Devin's Critic) before push/PR
   - Security checks (no secrets in code)
   - Logic validation (tests pass)
   - Code quality (lint passes)

2. **Self-healing loop**: On validation failure, auto-enqueue fix subtask (already in Phase 4)
   - Attach error logs to task record
   - Planner re-strategizes based on errors

3. **PR generation**: Include task description + validation results in PR body
   - Link to parent task
   - Attach artifacts (test results, lint output)

4. **Model-agnostic design**: Keep factory compatible with multiple LLMs (like OpenHands)
   - Agent integration already supports this
   - Config-driven model selection

5. **Sandboxing**: Enforce clean worktree cleanup even on failure (already in Phase 4)
   - No pollution of main workspace
   - Isolated execution environment

### Next Steps
- Phase 5: Implement push/PR creation with safety rails
- Phase 6: Multi-repo orchestration (like OpenHands' scalability)
- Phase 7: Feedback loop integration (GitHub reviews → re-planning)

## Factory Mappings — Coding Factory ↔ Devin AI Architecture

| Devin Component | Coding Factory Equivalent | Status |
|-----------------|--------------------------|--------|
| **Planner** | TaskManager + CodingFactory orchestrator | ✓ Complete (Phase 1) |
| **Coder** | AgentIntegration worker (spawns sub-agents) | ✓ Complete (Phase 3) |
| **Critic** | ResultValidator (validation gate) | ✓ Complete (Phase 4) |
| **Browser** | (future) web_search/web_fetch tool wrapper | Planned (Phase 5+) |

### Mapping Details

**Planner** (TaskManager + Orchestrator):
- Decomposes task requirements into steps
- Manages task queue (JSONL persistence)
- Re-plans on roadblocks (auto-enqueue fix subtasks)
- Indexes repo context (worktree isolation)

**Coder** (AgentIntegration):
- Spawns sub-agents to implement tasks
- Executes code inside isolated worktrees
- Learns frameworks via documentation (agent prompt)
- Handles multi-file changes (git worktree support)

**Critic** (ResultValidator):
- Validates execution results (lint/test/typecheck)
- Reviews for security, logic errors, test failures
- Blocks push/PR unless green (or explicitly overridden with "force" mode)
- Attaches error logs to task record for re-planning

**Browser** (future):
- Scrapes/synthesizes documentation (APIs, StackOverflow)
- Integrates web_search/web_fetch for context gathering
- Supports agent decision-making during execution

### Safety Rails (Phase 5)
- **Deterministic validation**: Parse lint/test/typecheck results
- **Force mode**: Allow override with explicit logging in task record
- **Default: NO push/NO PR** (behind explicit flag)
- **Clean worktree cleanup**: Enforced even on failure
